# 保留旧实例的重建与回退

## 重建前

记录旧 profile 路径、Lima 实例状态、共享源目录、磁盘位置、正在使用的会话。只备份用户需要的项目数据；不要从旧 VM 克隆磁盘、浏览器 profile、Cookie、账号令牌、Keychain 或系统机器身份。

准备新 profile 文件：新名称、新代理端口。默认要求用户提供不同节点及预期出口；如果用户明确要求沿用节点，才使用 `--reuse-node`。共享源可以相同，但在新旧实例间不要并发写同一文件；初验可用只读共享或独立测试目录。

```sh
python3 scripts/workstation.py --config /absolute/private/new.json rebuild \
  --from-config /absolute/private/old.json
```

该命令调用新系统安装，不使用历史“删除后同名重建”脚本。拒绝重复 profile、已有目标状态目录和重复端口，旧磁盘不动。系统安装生成新机器身份；浏览器使用新客户机默认数据目录，不从旧 profile 导入。普通 Chrome 不存在本包管理的“指纹种子”，不要把新磁盘等同于全新的所有硬件特征。

## 切换

完成新实例安装、完整 accept、冷启动 finish-acceptance、用户确认并 confirm-ui。检查新旧客户机 UUID 哈希确实不同。还没有通过就让旧实例保持原状，不能宣称切换成功。

用户需要实际业务登录时，让用户亲自完成；网络验收不能代替登录成功。用户接受新环境后，正常停止旧实例，更新用户日常入口指向新 profile。先保留旧实例及配置供回退。

## 失败与回退

候选验收失败会取消收据并保留阻断。不要为使测试“通过”关闭 PF、改成 DIRECT 或继承 Clash。回退时正常停止候选，按旧 profile 的正常启动流程重新检查网络后进入旧实例。共享是同一份数据，回退磁盘不会撤销共享文件修改；涉及数据迁移需单独备份。

本包没有自动删除旧盘的命令。只有用户明确指定旧实例并同意删除后，才使用对应独立 LIMA_HOME 的 limactl delete，删除前再次核对实例名和磁盘目录。不要用 rm -rf 清理整个 Lima home，不默认强制断电。
